# DoL 中文网页版

当前版本：**0.5.12.13-chs-1.0.1a**，汉化组正式发布，ModLoader 2.101.1。

- 入口：`index.html`。首次升级前在本机保留 localStorage、sessionStorage、DoL 存档数据库及模组缓存的不可覆盖备份，然后进入新版。
- 备份下载：`backup.html`。JSON 为本机恢复包；标准游戏存档请通过游戏内存档菜单导出。
- 旧版本：`legacy.html`，保留完整 0.5.0.6 中文游戏与原内置模组，可用于读取并导出旧存档。
- 保留相同的故事 IFID、SugarCube 存档 ID 与 DoL 存档数据库名，不清理浏览器存档。新旧模组缓存使用不同键，避免旧模组覆盖新版。
- 保留原有作弊入口、成就限制调整和战斗数值显示；旧版两个自定义模组原始文件保存在 `mods/legacy/`。

官方来源与 SHA-256 校验记录见 `upstream-release.json`。`tools/upgrade_dol.py` 可从固定官方发布重建全部安装文件；`.github/workflows/upgrade.yml` 在独立 Chromium/WebKit 测试档案中验证两种旧存档格式升级、中文显示、模组及自动备份。

不要清理站点数据；手机浏览器的存档仅存在该手机。切换浏览器或设备前请导出标准游戏存档。

## 完整整合包与离线加载

`game.html` 内置汉化包、原版图片包和兼容 Mod，启动时禁用远程 Mod 列表，不再逐个下载 ZIP。启动检查要求汉化与兼容补丁初始化完成，防止静默落入英文原版。

首页在备份成功后显示完整游戏的下载进度。Service Worker 将完整游戏缓存到本机；后续优先使用缓存，并支持断网后从原网址重新进入。缓存缺失、网络连续 30 秒无数据或初始化失败均显示错误或重试入口。

`dol-0.5.12.13-chs-1.0.1a-offline.zip` 是可下载的完整包。解压后，用支持 JavaScript 的桌面浏览器打开「开始游戏.html」。离线文件与原网站的存档空间不同，继续原进度应先导出标准存档再导入。iPhone 的文件预览通常不支持运行这类游戏，推荐使用缓存后的网页版。

验证说明：首次进入的中文界面和两种旧存档均在 Chromium/WebKit 中检查。Chromium 通过浏览器断网模拟验证缓存重开；WebKit 因 Playwright 的已知断网模拟问题（microsoft/playwright#42775），通过停止真实测试服务器并确认网络请求失败后，再验证缓存重开。独立 HTML 在桌面 Chromium 中完全断网运行。

## BESC＋UCB 美化版

游戏版本和存档标识保持不变。美化资源来自 DoL-Lyra `v0.5.12.13-1.0.1a-1004.1` 的 BESC＋UCB 配套包，并核对发布的 SHA-256。`art-manifest.json` 记录源文件、图片数量及人物/服装/场景图片样本校验值。新图片包是唯一的原图/美化图片提供者，避免原版图片包覆盖静态美化。

从 `play.html` 进入可绕过旧版 Service Worker 的入口缓存。新版入口会等待对应版本的缓存组件就绪，并完整缓存游戏 HTML 和美化图包，启动时从缓存读取美化包；缺失时显示下载错误，不静默退回原图。保留旧缓存和全部存档。

带美化的完整离线 ZIP 在浏览器检查全部通过后发布到本仓库 Releases（`dol-web-besc-ucb-3`），其中包含可独立运行的完整 HTML。原来的无美化 ZIP 仍保留。

启动修复 startup-4：已有备份仅用 IndexedDB count 检查存在性，不在每次打开时完整反序列化大型备份。备份、缓存组件、文件缓存及版本清单各自显示状态；缓存打开和读取超时会显示重试。`launch.html` 是新的入口，游戏和美化缓存仍使用 build 3，不因入口修复重新下载已有文件。

启动修复 startup-5：缓存组件使用兼容的游戏 build 判断，允许继续使用 build 3 的已有组件，不再要求入口脚本版本握手。新组件安装只执行 skipWaiting；页面离线缓存随后尽力保存，失败不阻碍激活。组件注册、激活或文件缓存无法使用时自动进入 `online.html`。该文件与 `game.html` 完全相同，汉化、美化和存档标识不变；`start.html` 提供新入口和始终可点的在线链接。

## 手机分块加载（mobile-6）

`mobile.html` 是几 KB 的加载入口，不直接导航到 83MB 游戏文档。游戏文档按独立 gzip 小文件加载并校验、解压，再写入同一 origin 和 URL 的文档；模组 ZIP 也分成不超过 512KB 的资源，失败可自动重试。初始必需资源约 33MB，完成的资源使用浏览器正常 HTTP 缓存，不依赖 Service Worker 或 CacheStorage。

BESC/UCB 图片保持原图字节，使用去重的静态文件按显示需要加载，不在启动前下载整个 80MB 图片包。游戏、汉化、兼容补丁、存档 ID 和 IndexedDB 名保持不变，旧完整入口和离线包仍保留。构建脚本为 `tools/build_mobile.py`；测试覆盖断连重试、两种真实旧存档、汉化、静态人物/服装/场景图的哈希，以及禁用缓存组件时的启动。

## 作弊菜单衣柜容量

手机版的“作弊 → 其它”顶部增加卧室衣柜容量控制，支持 ±1、±10 格（每类衣物的上限）。容量不会降到任一类已有衣物数量以下；只修改容量数值，不删除衣物。选择值记录在游戏状态中，正常存档即可保留，并在家具更新重新计算容量后恢复该值。

## 请求限速与冷却

游戏分块和按需图片共用请求队列，同时最多两个请求，请求起点至少间隔 150ms。遇到 HTTP 429 时按 Retry-After（秒数或 HTTP 日期）暂停全部后续请求；缺少该头时使用递增冷却。冷却期限在当前标签页保留，刷新后也不会立刻追加请求。连续限流三次后停止请求并提示稍后重试。队列直接内置在小入口中，不额外依赖离线组件或保存用户存档数据。
